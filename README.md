# Flux — Cloudflare Python Worker (Phase 1)

This repository contains the first Cloudflare-native migration slice of Flux. It is **not** the original long-running Python app copied unchanged: Cloudflare Workers are event-driven and use webhooks rather than a permanent polling process.

## Included in Phase 1

- Telegram webhook endpoint with Telegram secret-token validation.
- Optional owner-only bot handling when `TELEGRAM_OWNER_ID` is set.
- `/start` and `/help`.
- AI text chat through the Anthropic Messages API.
- Persistent recent conversation history in Cloudflare D1.
- Live Startup Intelligence fetches from Reddit, GitHub Search and Hacker News Algolia.
- `/startup`, `/startup_scan`, and `/startup_auto on|off`.
- 30-minute Cron Trigger. Automatic scanning starts OFF.

## Not included yet

The original `flux.py` has Gmail/Google Calendar, flights, product search and price alerts, voice, image/file handling, WhatsApp, approvals and a Flask dashboard. Those features are **not active in this Worker phase**. They require separate Cloudflare-compatible implementations and tests. Do not assume they work just because this Worker deploys.

## Existing D1 database setup

The current D1 database was created first with the tables `users`, `memories`, `reminders`, `startup_items`, `scan_runs`, `product_watches`, and `flight_watches`.

1. Open the existing D1 database in Cloudflare Dashboard.
2. Open **Console**.
3. Paste and execute the contents of `setup_existing_d1.sql` **once**. This adds only `chat_history`, `settings`, and two columns used by Startup Intelligence. It does not delete or replace the tables already created.
4. Do **not** run `migrations/0001_initial.sql` on this already-created database: it was designed for a brand-new database and its index expects a different initial `startup_items` shape.

## Worker configuration

- `wrangler.toml` is already configured with D1 binding name `DB`, database name `flux-db`, and the D1 ID supplied for this project.
- Set `TELEGRAM_OWNER_ID` to your numeric Telegram user ID before relying on owner-only protection. Leaving it empty means the Worker does not apply that extra user-ID check.
- Keep all API tokens out of GitHub. Add these as Worker **Secrets** in Cloudflare:
  - `TELEGRAM_BOT_TOKEN`
  - `TELEGRAM_WEBHOOK_SECRET` (a random value of at least 32 characters)
  - `ANTHROPIC_API_KEY`
- `ANTHROPIC_MODEL` is set to `claude-sonnet-5-5`.

## Deploy

The repository is intended to be connected to Cloudflare Workers & Pages using its Git integration and the Python Workers runtime. Use the build/deploy instructions generated by Cloudflare for this Python Worker project. After deployment:

1. Test `https://<worker-name>.<your-subdomain>.workers.dev/health`.
2. Configure Telegram's webhook to `https://<worker-name>.<your-subdomain>.workers.dev/telegram/webhook`, passing the same webhook secret as Telegram's `secret_token`.
3. Send `/start` to the bot.

## Important limits

Hosting the webhook on Cloudflare does not make the original app a continuously running Python process. The Worker wakes for requests and scheduled events. Anthropic API usage and any future third-party integrations can incur separate charges. Validate webhook delivery and source API responses before enabling automatic scans.
